# Behavioral Deviations

Every confirmed difference between the original Thaumcraft 4.2.3.5 /
Baubles 1.0.1.10 behavior and the modern port, with cause and impact.
Per the project brief, a deviation is an exception that requires evidence
and documentation — not a redesign. The default is to preserve original
behavior; each row below records why exact preservation was not achieved
and what remains to eliminate it.

Status vocabulary: **UNAVOIDABLE** (target platform cannot express the original), **TEMPORARY** (a tracked task exists to close it), **ACCEPTED** (decision recorded in `porting-decisions.md`), **RESOLVED** (was a deviation, now matches the original), **ADAPTED** (the ported seam is algebraically equivalent where the original's constant is not measurable from `reference/`), **N/A** (the original has no counterpart, so parity is preserved by construction), **PERMANENT** (closed by decision; it will not be eliminated), **PARTIAL** (the shipped half is named, the remainder is a filed card), **CLOSED** (this half of the row is done; the row stays for the rest), **BY POLICY** (the shape follows a recorded decision, not a platform limit), **DEFERRED** (the row ships a contract and names what it defers).
Measured over the whole ledger, every row's status uses one of these tokens;
`BehavioralDeviationLedgerContractTest` parses this paragraph and requires every row
to carry a declared token.

**Numbering after INTEGRATE-BOOK-LANES (t_ee886c7e).** Two lanes numbered the
same rows independently: `main` a084fc8 ran to BD-19, the BOOK lane
(7a1108a) added BD-20/21/22 and kept BD-17/18/19 for item models, taint and
wisp FX, and the research lane had re-used BD-17/18/19 for its own Thaumonomicon
presentation, research note item and note-request rows. The merge keeps the
BOOK lane's BD-17/18/19 and renumbers the research lane's three rows to the
free block: **BD-17 (research) → BD-23** (Thaumonomicon presentation),
**BD-18 (research) → BD-24** (research note item),
**BD-19 (research) → BD-25** (note request + Scribing Tools). The research
lane's BD-13/14/15/16 rows were duplicates of the BOOK lane's and are gone:
its BD-13 text is merged into this file's single BD-13 row. Every
cross-reference in `content-mapping.csv`, `FEATURE_MATRIX.md`,
`feature-tracking.md` and `compatibility-matrix.md` points at the new numbers.


**Ledger id space is `main`'s (ledger reconcile t_9a2c9f91, base `7933db8`).** The
same file carried 14-30 rows across 100+ live heads while `main` carried 45, and
three different rows claimed `BD-19` on three sides of three landings. The rule is
mechanical in `scripts/bd_ledger.py` and machine-checked by
`BehavioralDeviationLedgerContractTest` (in `./gradlew test`, CI's `build` job):

- `main`'s rows are the **incumbent**: their ids and their text are kept verbatim.
  A landing never renumbers to match a branch's numbering and never trims rows to
  make a count agree — those two moves are what produced the divergent ledgers.
- A deviation a head carries that `main` does not is appended at the first free id
  after the incumbent block (`BD-46` and above), verbatim, with its source head,
  sha, the id that head used and the landing card named in the row's last cell.
- A head's row is **rejected** — not appended — when `main` already owns that
  deviation: as a row main rewrote, as a re-wording of a main row, or as text
  main's ledger narrates. The adjudications measured at this base are pinned in
  `ADJUDICATED` in the tool: `Container screen backgrounds and client-visible
  machine state` -> **BD-37** and `Wisp block collision` -> **BD-19**.
- `docs/bd-id-map.csv` (generated by `python3 scripts/bd_ledger.py emit`) is the
  old -> new mapping every pending landing cites: rewrite your branch's citations
  to the allocated id, and where the map says your row is covered, edit that
  incumbent row's cells at landing instead of adding a row.
- The contract asserts the row count never decreases, the incumbent rows survive
  verbatim, ids are unique / zero-padded / contiguous, every `BD-NN` citation in
  the tree resolves to exactly one row, every row carries a declared status
  token, and the map resolves. A merge that takes one side of this file
  wholesale goes red.
- Land one ledger edit at a time: this file is in the conflict set of every
  queued landing, and `python3 scripts/bd_ledger.py revert` reports the
  incumbent rows a head's merge would delete (it must stay 0).

## How to add a deviation

A new row is required whenever a committed change makes the port behave
differently from the original in any observable way (gameplay, visuals,
